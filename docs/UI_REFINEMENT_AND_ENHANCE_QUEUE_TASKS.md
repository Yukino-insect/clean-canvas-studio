# UI 统一与画质增强任务队列：需求与实施台账

> 本文针对“内容修复页比例失衡、导航展开策略、增强页视觉不统一、增强任务无法批量管理/记录日志”的重构需求。参考基线为 `D:\Project\python\me\video-subtitle-remover\ui` 的卡片、预览、日志、任务队列与处理期预览交互。状态：`未开始`、`进行中`、`已完成`。

## 1. 现状审计

| 编号 | 发现 | 根因 | 影响 |
| --- | --- | --- |
| A-01 | 左侧导航曾被改为浮层覆盖预览。 | 为避免窗口被最小尺寸撑大，错误改变了导航展示策略。 | 与参考版交互不一致，展开后遮挡业务内容。 |
| A-02 | 内容修复页右侧曾挤压视频预览；按钮出现过截断或过大空白。 | 设置说明、长下拉文本和操作按钮的尺寸策略混杂；五按钮布局缺少自然换行。 | 预览不再是视觉重点，按钮比例失衡。 |
| A-03 | 增强页使用普通 `QComboBox/QLabel`，与内容修复页的 SettingCard/CardWidget 体系不同。 | 增强页初期为独立原型，未复用应用级设计语言。 | 页面像两个不同应用拼在一起。 |
| A-04 | 增强页只能选择一个文件、运行一次，没有任务表和可选任务预览。 | `EnhanceInterface` 直接持有单个 `media_path` 和一个 worker。 | 无法批量处理图片/视频，用户不能管理队列。 |
| A-05 | 增强页没有完整日志区域，状态只能看一行标签。 | `MediaEnhancer` 只回调进度，没有日志/预览协议。 | 下载、模型、编码、失败和输出路径难以追踪。 |
| A-06 | 内容修复任务运行时预览原图/结果；增强任务没有等价机制。 | `MediaEnhancer` 没有 preview listener。 | 视频增强长时间运行时缺乏过程可见性。 |

## 2. 设计原则

1. **导航策略恢复参考版。** 宽窗口采用内嵌展开的 `322px` 侧栏，内容重新布局；窄窗口由框架自动使用菜单浮层。窗口不扩张依赖于业务页面的合理最小宽度，而不是把导航改成覆盖层。
2. **预览优先且可用。** 内容修复与增强页都使用左侧预览、右侧设置/任务、下方日志的稳定结构；不可用时缩小，但不以隐藏文本或无意义大空白换取表面整齐。
3. **完整说明不占主空间。** 设置卡显示一行简短决策摘要；完整说明通过 tooltip、日志或专门文档提供。
4. **任务是数据，不是一次点击。** 增强页每个媒体都有独立的输入路径、输出路径、模型、倍率、设备、状态和进度；队列可按顺序执行。
5. **运行期预览必须节流。** 图片完成后显示输出；视频处理期显示“输入（缩放到输出尺寸） | 当前增强帧”的对比预览，但按固定帧间隔发送，不能每帧向 GUI 传全尺寸数组。
6. **GUI 与后端协议分离。** `MediaEnhancer` 只发进度、日志和预览回调；Qt 页面通过 Signal 回到主线程更新表格、日志和预览。

## 4. 目标界面结构

```text
内容修复 / 画质增强页面
┌──────────────────────────────┬──────────────────────────────┐
│ 媒体预览（输入/输出/对比）     │ 设置卡                       │
│ 16:9 黑底画面与时间轴/状态     ├──────────────────────────────┤
├──────────────────────────────┤ 任务列表：名称 / 进度 / 状态 │
│ 日志：时间、任务、提示、错误   ├──────────────────────────────┤
│                              │ 操作：添加 / 开始 / 停止     │
└──────────────────────────────┴──────────────────────────────┘
```

宽窗口导航展开时采用参考版内嵌侧栏：

```text
48px 紧凑导航 -> 322px 内嵌导航
                    + 内容区重新布局
                    + 顶层窗口尺寸不变
```
