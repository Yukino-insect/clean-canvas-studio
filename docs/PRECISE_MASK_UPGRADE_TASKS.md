# 精确掩膜升级：需求、设计与实施台账

> 本文是 OCR 精确掩膜阶段的唯一任务台账。状态只能为 `未开始`、`进行中`、`已完成`、`阻塞`；实现、测试与文档必须同步更新。

## 1. 当前链路审计与结论

当前流程不是“精准文字掩膜”，而是：

```text
PaddleOCR TextDetection
  └─ dt_polys（文本多边形）
       └─ backend/tools/ocr.py:get_coordinates()
            └─ 丢弃四个顶点，收束为内接矩形 (xmin, xmax, ymin, ymax)
                 └─ regions_to_mask() 填满矩形并全局膨胀
                      └─ OpenCV / LaMa / Anime-LaMa 修复整块矩形
```

因此，现有实现在两个地方损失了精度：

1. PaddleOCR 已输出 `dt_polys` 和 `dt_scores`，但程序只保留了错误收束后的矩形；斜排文字、弯曲布局和紧邻角色轮廓时会吞掉大量背景。
2. 用户在界面画的框目前被确认后直接当成最终掩膜；它无法表达“只擦文字笔画、不擦框内背景”。

`TextDetection` 的确支持 `thresh`、`box_thresh`、`unclip_ratio`、`limit_side_len` 与 `input_shape`。不过它输出的是**文本区域轮廓/多边形**，不是字符笔画级语义分割，也不能识别“任意符号、logo、人物”等非文字对象。所谓“精准”必须按来源分层处理，不能把 OCR 检测框误称为像素级抠图。

## 2. 目标掩膜类型与用户提供的信息

| 掩膜类型 | 最终擦除区域 | 用户需要提供 | 适用对象 | 风险 |
| --- | --- | --- | --- | --- |
| 手工矩形 | 整个矩形 | 画一个或多个框 | 非文字符号、logo、需要整块移除的对象 | 会覆盖框内背景，兼容旧行为。 |
| OCR 多边形 | `dt_polys` 填充的多边形 | 可选候选 ROI；确认 OCR 框 | 字幕、印刷文字、规则艺术字 | 仍是文字外轮廓，不是笔画级。 |
| OCR 多边形 + 轮廓细化 | 多边形内、且与周边背景颜色差异明显的连通区域 | 候选 ROI、阈值/极性/最小面积 | 高对比文字、描边文字 | 纹理背景、渐变或同色人物边缘可能误选；必须可预览回退。 |
| 混合掩膜 | OCR 多边形与手工矩形并集 | 文字候选 ROI + 手工符号框 | 文字和非文字干扰物同时存在 | 手工部分仍是矩形，需清楚区分颜色和来源。 |

结论：用户画的框在“精确 OCR”模式中只能是**候选 ROI/筛选器**；在“手工矩形”或“混合”模式中才是明确的擦除范围。所有模式都需将最终掩膜回显给用户确认。

## 3. 视频策略与性能选择

对 30 FPS、10 分钟视频逐帧 OCR 需要约 18,000 次检测；以当前 CPU PaddleOCR 估算，通常不可接受。因此把“掩膜来源”和“视频更新频率”分开配置。

| 视频策略 | OCR 次数 | 最终掩膜 | 适用场景 | 代价 |
| --- | ---: | --- | --- | --- |
| 确认帧静态掩膜（默认） | 1 次/用户确认 | 将确认帧的精确多边形复用于 A/B 区间 | 固定位置、固定字形字幕/台标 | 最快；移动或换行字幕会错位。 |
| 采样 OCR 多边形 | 每 2–4 帧（按 FPS 自适应） | 检测帧多边形；中间帧使用相邻样本的并集 | 轻微移动字幕 | 中等；比矩形精确，但边界帧会稍保守。 |
| 逐帧 OCR 多边形 | 每帧 | 每帧独立多边形 | 位置/内容频繁变化的短片段 | 最慢；作为明确的“高精度”选项，不作为默认。 |
| 手工静态矩形 | 0 次 | 确认矩形复用 | logo、符号、无 OCR 文本 | 最快；不精准。 |

高精度模式只优化掩膜定位，不会让单帧 AI 修复自动获得时序一致性；Anime-LaMa 逐帧处理长视频仍可能闪烁。

## 5. 界面参数设计

### 去除页面的模式

| 控件 | 默认 | 说明 |
| --- | --- | --- |
| 掩膜模式 | OCR 多边形 | 决定最终掩膜，不决定 AI 修复模型。 |
| 视频掩膜策略 | 确认帧静态掩膜 | 图片无此项；视频可改为采样或逐帧。 |
| 文字检测像素阈值 | 0.3 | 较低会找更多候选，误检也更多。 |
| 检测框置信阈值 | 0.6 | 低于该值的候选不纳入 OCR 掩膜。 |
| OCR 外扩系数 | 1.2 | PaddleOCR `unclip_ratio`；过大又会回到“粗框”问题。 |
| 掩膜边缘扩张 | 2 px | 覆盖抗锯齿与描边残留；在最终 mask 阶段生效。 |
| 轮廓细化色差 | 22（Lab） | 仅细化模式；低值更严格，高值更保守。 |
| 最小连通域 | 8 px | 过滤噪点；太高会丢细小标点。 |

### 交互规则

1. 用户框选区域在 OCR 模式中显示为黄色“候选 ROI”，不会直接擦除。
2. OCR 多边形显示为青色，最终 mask 显示为半透明红色；手工矩形显示为橙色。
3. 点击确认时保存的是最终 `MaskPlan`，而不是显示框；之后修改参数或 ROI 会使确认失效。
4. 若 OCR 未找到目标，用户可切换“手工矩形”或“混合”来处理非文字符号；本阶段不假装 OCR 可以识别任意对象。

## 6. 实施顺序

1. PM-01 / PM-02：恢复和验证 PaddleOCR 多边形，建立可靠的掩膜基础。
2. PM-03：实现可回退的本地轮廓细化，不添加重型模型依赖。
3. PM-04 / PM-05：固化 `MaskPlan` 并把模式接入图片处理。
4. PM-06：再接入视频的三档策略，避免逐帧 OCR 被默认启用。
5. PM-07 / PM-08：完成可视化和参数设置。
6. PM-09 / PM-10：回归测试、验证记录和文档。

## 7. 实现与验证记录

| 验证项 | 结果 |
| --- | --- |
| PaddleOCR 数据保留 | 使用伪造 `dt_polys` / `dt_scores` 响应验证，四个顶点与 0.73 分数完整进入 `OcrPolygon`。 |
| 多边形而非矩形 | 倾斜四边形合成样图：多边形掩膜面积小于同一外接矩形，矩形角落不再被误遮罩。 |
| ROI 语义 | 候选 ROI 只筛选哪些多边形进入计划，测试确认它不会改变/填充多边形顶点。 |
| 轮廓细化 | 高对比文字样图中，细化掩膜小于候选多边形，保留文字区域；无结果时代码回退原多边形。 |
| 视频策略 | 5 帧合成视频：采样间隔 2 时 OCR 调用 3 次且填补中间帧；逐帧策略调用 5 次。静态精确计划已对 4 帧视频端到端输出成功且未调用 OCR。 |
| UI 冒烟 | 离屏实例化主窗口成功，最终掩膜模式、视频策略和全部精确掩膜参数卡可创建。 |
| 全量默认测试 | `python -m unittest discover -s test -p "test_*.py" -v`：12 项通过、2 项可选 AI 权重测试跳过。 |

当前实现没有引入新的大模型或网络下载；所有精确掩膜逻辑均基于现有 PaddleOCR 输出和 OpenCV。真实图片效果仍取决于文字检测是否命中以及文字与背景的颜色关系，确认前应以红色掩膜预览为准。
